# Upgrade to TenonAdmin 0.6.0

## What changed

| Area | Change |
|---|---|
| Packages | `TenonAdmin` / `TenonAdmin.Excel` **0.5.0 → 0.6.0** |
| Frontend | Re-extracted `web/` from `Tenon-Net/TenonAdmin/web#v0.6.0`; restored CRM + trial-login (patched onto the 0.6.0 `LoginForm`, which now has TOTP / SSO pending-link) |
| Roles | CRM demo roles set `IsDelegatable = true` and `SyncOnUpgrade = true` so a 0.5.x database picks up the new column on schema bump |
| HQ grants | Appended 0.6.0 system menus (user import/export, external-login / MFA, op-log export, job catalog). Existing `SysRoleMenu.Id` values 1100+ are unchanged |
| Tests | Idempotency host now also registers `CrmHqAdminSystemMenuSeed` (was missing vs `Program.cs`) |
| Scope banner | `GetScopeAsync` reads `IRepository<SysOrg>` (full tree). `IOrgService.ListAsync` is now scope-clipped (QA08) and would mis-label a partial subtree as "org and children" |

## Behaviour you will notice

0.6.0 has four breaking changes. This consumer does **not** use `AdditionalDatabases`, and CRM customer import is custom (not the kernel user-import template), so two of them do not apply. The other two do:

1. **Role assignment requires `IsDelegatable`.** Without the seed backfill, HQ admin could no longer grant the three demo roles on user save. Fresh DBs get `true` on insert; existing DBs get it on the kernel schema-version bump.
2. **Role definition / menus / data-scope are superadmin-only (QA36).** HQ admin still *sees* those menus (grants are append-only, we do not reshuffle seed IDs), but add/edit/delete role and menu/scope APIs answer **403**. Use `superAdmin` to define roles; HQ remains a real RBAC administrator for everything else, including granting the three delegatable demo roles.
3. **User and org lists honour data scope.** HQ role is `All` → unrestricted. South / Shenzhen stay scoped. Positions stay global.

Keep `CrmDemo:ImportDryRun=true` on the public host. Do **not** turn `TenonAdmin:DemoMode` on — it blocks every non-GET, including import POSTs.

## Reproducing packages from empty

```powershell
dotnet new install TenonAdmin.Templates@0.6.0
dotnet add package TenonAdmin --version 0.6.0
dotnet add package TenonAdmin.Excel --version 0.6.0
npx degit Tenon-Net/TenonAdmin/web#v0.6.0 web
```
