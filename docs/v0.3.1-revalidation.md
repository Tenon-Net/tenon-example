## Consumer Findings

1. **`dotnet run` fails on a fresh consumer, contradicting the README.** The generated project ships no `Properties/launchSettings.json`, so the environment resolves to `Production`, `EnableCodeFirstInProduction` defaults to false, CodeFirst is skipped, and startup throws `InvalidOperationException` naming the twelve missing seed tables. An empty `data/admin.db` is left behind. Reproduced three ways: plain `dotnet run` here, `dotnet run -c Release` here, and `dotnet run` in the clean-room project generated from the published template. The kernel's own `backend/samples/MinimalHost` does ship a launch profile pinning `ASPNETCORE_ENVIRONMENT=Development`, so the template is the gap. Workaround used for this validation: `ASPNETCORE_ENVIRONMENT=Development dotnet run`. This is the highest-severity consumer finding so far — it breaks the advertised zero-configuration first command — and it is reusable, so it belongs upstream.
2. **`npm audit` reports 7 high advisories, all in build-time tooling.** Two chains: `brace-expansion` DoS through `minimatch` into `@redocly/openapi-core` / `openapi-typescript` (the `gen:api` toolchain) and into `@vue/language-core` / `vue-tsc` (the typecheck toolchain); and `postcss` path traversal below Vite. Neither reaches the browser bundle. The advisories postdate the `0.3.1` release, and the `brace-expansion` chain is only fixable through a breaking `vue-tsc@3` bump, so no release-pinned dependency was changed here.

The `0.3.0` findings are closed: the `dotnet new` restore post-action now reports success, and the five `npm install` advisories, the deferred install-script approvals, and the `git diff --check` findings in the frontend source are all gone in `0.3.1`.
