# v0.3.3 Upgrade

Date: 2026-07-25

`0.3.3` shipped the fix for the third dogfood finding surfaced while deploying this repository to production: the `tenon-app` template's `Dockerfile` broke for any hyphenated project name (`dotnet new` sanitizes hyphens to underscores when substituting the project name into file *content*, but keeps the literal name when renaming files, so the generated Dockerfile referenced a `.csproj`/`.dll` that never existed). This repository's own `Dockerfile` was already fixed directly (commit `b39565e`, same session) ahead of the upstream template fix landing, so this upgrade is a version-alignment bump, not a functional change.

## Changes

- `tenon-example.csproj` now references `TenonAdmin` `0.3.3`.
- `web/` was **not** re-extracted: `git diff v0.3.2 v0.3.3 -- web/` on the TenonAdmin source repo shows zero content changes (only the template's own version-string bump), and this app's `web/` already carries local CRM and login-page work (P3's `views/crm/customer/index.vue`, `api/crm.ts`, `types/crm.ts`, `locales/ext/*/crm.ts`, plus the quick-login additions to `views/login/LoginForm.vue`) that a forced `degit` would destroy. Re-extracting is only warranted when the upstream template actually changed something relevant.
- TenonAdmin tag `v0.3.3` on `Tenon-Net/TenonAdmin`.
